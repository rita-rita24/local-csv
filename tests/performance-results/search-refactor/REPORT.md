# 連続検索の追加整理・検証（2026-10-10）

## ① 実施結果

検索・置換・検索Workerで重複していた正規表現の組み立てを、DOMに依存しない `_buildSearchRegex` / `_buildSearchMatcher` に集約した。Workerには同じ関数のソースを渡す。自己完結HTMLと紹介ページの埋め込み本体を同期した。新しい依存や製品内の計測通信は追加していない。削除済みの旧ファイル名を参照していた紹介ページの6リンクと埋め込み属性を現行名へ合わせ、JavaScript無効時も実在するファイルを参照するよう修正した。静的検査は紹介ページの全ローカルhref/srcの実在を検査する。

## ② 現代化の追加内容

同じ検索意味論を3か所で手書きしていた状態から、共通の純粋な正規表現生成に変更した。検索matcherの組み立て2か所と置換1か所を移行し、この重複の残件は0か所。独自の文字エスケープを再導入せず、前回採用した `RegExp.escape` と必要な旧環境分岐を使う。基本的なRegExpやPromiseなど現在有効なAPIは、導入年のみを理由に禁止していない。

公式根拠は [ECMAScript 2026 RegExp](https://tc39.es/ecma262/2026/multipage/text-processing.html#sec-regexp-constructor) と [RegExp.escape](https://tc39.es/ecma262/2026/multipage/text-processing.html#sec-regexp.escape)。安定標準であることを前回監査で確認した。使用構文と配信互換性を維持した。完全一致には末尾改行直前でも一致する `$` を使わず、既存の厳密な境界判定を保持する。

公式資料確認日: 2026-10-10 JST。件数は手書きの実装箇所またはリンク要素の数で、生成された同一ソースを二重に数えない。
