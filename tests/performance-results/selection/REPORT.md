# 全選択・列選択の実測と開発環境の更新

## ① 実施結果

全選択と1列選択の行モデル構築を `_selectVisibleColumns` にまとめ、セルごとのMap再取得を省いた。行ごとに独立したSetを作り、数値の列範囲を直接追加する。表示中の行、列範囲、コピー対象、空の表・不正列の動作は保持した。紹介ページの埋め込みHTMLも同期した。

開発用の推奨Nodeを24.21.0 LTSへ更新し、公式配布物のSHA-256を照合した一時実行環境でbuild・静的検査・回帰を実行した。元のホストNode22.22.2は変更していない。CIは22/24のmatrixに変更し、全選択/列選択の一致試験も追加した。

**依頼全体は未完了。本番未反映・本番未計測、全面の意味監査・全操作の計測・目標達成・最低ブラウザ確認は残る。** 本番URLと通常の公開手順は以前の質問に対する回答がなく未特定。前回確認したGitHub配布入口を、通常の公開手順の確認なしに更新していない。package版は1.2.6、Git HEADは1e2fc63、今回の識別はversion.json。着手前の大量の未コミット変更を保持した。

## ② 現代化・整理

|言語/領域|旧実装|採用した実装|変更前|移行済み|必要な例外|未対応|単位・範囲|

Map / Set / for / forEach は現在も有効な標準であり、「旧APIを廃止した」とは扱わない。今回の整理は重複と不要な検索の除去である。APIの新しさだけを目的に採用したSet(iterable)候補が遅かったため、従来のSet.add経路を採用した。

公式資料確認日: 2026-10-10 JST。[ECMAScript 2026のSet](https://tc39.es/ecma262/2026/multipage/keyed-collections.html#sec-set-iterable)、[Node公式リリース一覧](https://nodejs.org/en/about/previous-releases)。公式ページのLatest LTSは24.21.0、Currentは26.11.1。安定した開発運用としてLTS24を選び、同じ公式ページでLTSの22も互換CIに保持する。配布製品は静的HTMLで、ブラウザが本番の実行環境であり、本番Node24稼働とは報告しない。

選択の状態変更を確認した。初期化、clearSelectionModel、空の表の描画、可視行/有効列のprune、単セル/範囲追加、今回の一括構築がMap/Setの変更箇所。行間で同じSetを共有せず、選択を保存データへ書き込まず、既存の見える行順の取得とコピー時の整列を維持する。これは選択処理に対する意味監査であり、未確認の他処理まで完了扱いしない。

## ③ 変更前・後の操作時間

事前に本体を保存し、100,000行×20列の全選択、全選択の反復、1列選択を各7回実行した。正しい200万セル/10万セルの選択コピーと、復元した元CSVが一致した。その後、実装前にtargets.jsonへ全選択の結果確定20%短縮、列選択と描画機会の中央値15%超の悪化を避ける目標を数値で記録した。最初の変更前の初回中央値57.4ms/反復58.3msを基準に、結果確定の絶対目標を45.92ms/46.64msとした。

3候補を比較した。全候補で正しさは一致したが、最初の2候補は遅いため不採用。

|Set(列一覧)|57.4 / 58.3 / 6.2|81.2 / 79.5 / 17.3|目標未達。採用せず|
|列一覧のfor-of+Set.add|同上|95.5 / 93.2 / 12.5|目標未達。採用せず|

短縮率は `(前−後)/前×100`。全6指標で範囲が重なり、差の確定とは扱わない。交互測定の中央値は全選択で短いが、事前の結果確定目標は未達。列の中央値はほぼ同じ。原因はMap再取得の削減というコード上の仮説までで、Map.getの実時間やCPU self-timeを分離した証明はない。

開始点は実際のコマンド/列メニューの確定click。正しい選択数の通知が更新され、同期処理が終わったMutationObserverの時刻を結果確定として記録した。第2rAFは別指標の描画機会であり、GPUの表示完了やINPとは扱わない。モーダルを閉じて実行する既存のsetTimeout経路を保持し、新しい待ち時間は製品に加えていない。取込・初期化・初期保存・メニューを開く準備・コピー確認はこの時間から除く。

環境: Chrome154.0.8037.99、Node22.22.2のドライバー、1440×900、日本語ロケール、毎回新しいcontext、file:起動。OSの実クリップボード権限はfakeで制御し、コピーの全バイトを照合した。実OSへのコピー待ち時間は未計測。本番の前後値・短縮率は未計測・算出不可。

## ④ 引っかかり・連続操作

交互計測のLong Tasksは、変更前の全選択に1件88ms、反復に1件86ms、変更後は両方0件。列選択は前後0件。7標本の観測であり、50ms未満の処理、入力待ち、描画、OS負荷はこのAPIの対象外。引っかかりゼロや60FPS達成とは報告しない。長い処理の原因分離や低性能実機・120Hz・長時間メモリの検証は残る。

全試行で、全選択/反復の200万セルと1列の10万セルが期待したTSVと一致し、1セルまで縮小すると全文編集が有効になった。再読み込み後の100,000行全CSVも一致した。絞り込み中の行順、ragged rows、独立したSet、空の表、不正列による選択の保持、更新1回はNode回帰へ追加した。
